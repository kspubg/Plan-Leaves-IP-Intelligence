# 关联账号处置、撤销与观察

本功能仅在当前 Leaves / Paper / Bukkit 实例执行原生命令，不会向其它子服远程发送命令。必须使用登录用户及单独的管理权限；关闭认证不会开放封禁接口。

## 登录与权限

保留原来的数据库、服务器身份文件、地区数据库以及全部个性化配置，只新增以下选项：

```yaml
Webserver:
  Security:
    Disable_authentication: false
    Allow_HTTP_authentication: true
    Disable_registration: true
Data_gathering:
  IP_intelligence:
    Enabled: true
    Subnet_alerts: false
```

这是现有配置中的嵌套键，不要重复添加整个 Webserver 或 Data_gathering 节点。HTTP 登录是明确选择的兼容模式，**密码、会话及玩家 IP 均没有传输加密**。有登录不等于 HTTP 安全，建议使用 VPN、SSH 隧道或可信网络，不需要开放 443。HTTPS 模式仍保持 Secure Cookie。

使用 Plan 原有网页用户 / 控制台注册流程创建自己的账号，不提供或预置正式服管理密码。若需要网页注册，临时启用 Disable_registration: false，完成控制台确认后再关闭注册。

在 Plan 原生「用户组」管理中给受信任管理组授予：

- `page.ip.intelligence`：查看 IP 与地区分析。
- `manage.ip.moderation`：预览 / 执行封禁、管理观察名单、忽略提示。Plan 的权限为层级关系，此父权限也包含下面的撤销权限。
- `manage.ip.moderation.undo`：只授予此子权限可允许撤销而不允许新封禁。
- 原有页面访问权限仍需保留（例如相应的 `access.server`）。

不会自动提升已有 admin 或其它用户组的权限。无登录、只读用户、无管理权限用户均不能执行操作。

**这些是 Plan 网页用户组权限，不是 LuckPerms 游戏权限。** 即使游戏账号是 OP、在 LuckPerms 授予同名节点，或者网页账号属于旧的 `admin` 组，也不代表已有 `manage.ip.moderation`。使用有 `manage.groups` 权限的网页账号进入「用户组」，编辑对应组、添加该权限并保存；退出并重新登录确认生效。仅给可信管理员所在组添加权限，不要给所有网页用户开放封禁。控制台 `plan setgroup <网页用户名> <网页组名>` 只切换网页组，不会给该组添加权限。

导入旧备份时检查 `public_html`：该目录中的自定义 React 静态资源可能覆盖 JAR 内的新前端。如果有旧 `index.html` / `assets`，先备份并逐项确认再停用旧覆盖，保留自己仍需使用的其它静态文件。空目录不会覆盖新前端；不要删除整个 Plan 数据目录或玩家数据库来刷新网页。

## 整组封禁

玩家列表「封禁关联账号」→ 选择该玩家的精确历史 IP → 预览所有已记录关联账号 → 必填说明 → 最终确认。

全部关联账号只读展示，不提供单账号排除；只针对所选精确 IP，不自动扩展到关联账号的其它历史 IP，也不根据网段封禁。预览有效期五分钟，执行前重新核对账号 UUID 与游戏名。整组账号身份必须与服务器已有缓存相符，任何一个无法核对都会在原生命令前拒绝本组操作；不会在线查询陌生名字来猜测身份。超过 200 个关联账号拒绝批量执行，避免误封大型共享出口。

服务器调度器通过控制台执行固定的 `minecraft:ban` 与 `minecraft:ban-ip`；每项结果独立显示。原有封禁保持原样，本次新封禁附加唯一操作标记。流程结束不代表所有命令成功，请查看逐项状态。

共享 IP 可能来自家庭、校园、移动网络 NAT 或代理，不能证明账号属于同一人。IP 封禁还会限制该地址下没有记录的其它用户。务必人工核实地址与最近活动，动态 IP 可能已分配给无关玩家。

## 撤销和崩溃处理

在审计记录中打开详情后撤销：只解除本次操作新增且原因、来源、时间、有效期仍与执行后快照一致的处罚。原本就有的封禁不会解除；后来被其它管理员修改的封禁标为冲突并保留。部分失败或冲突显示为「部分撤销」，不承诺回到全组完全未封禁状态。

重复提交同一预览不会再次封禁，即使该操作已经撤销。失败后如需再次封禁，应重新预览并核查记录。

每条命令前持久化意图。崩溃留下 PENDING / APPLYING 等记录时不会自动重放封禁，也不会猜测归属并解除处罚；管理员需对照原生封禁文件人工核对。审计文件损坏或写入失败会停止管理操作，不会为了继续执行而重建空记录。

## 观察名单

玩家列表「加入观察」填写备注及 1–365 天期限。面板每 30 秒刷新（打开操作窗口或执行操作时暂停自动刷新）；没有后台自动封禁。打开 / 刷新面板时根据已采集 IP 历史计算新 IP 及共享精确 IP 提示，不向外部服务查询。

只用观察对象本人的原始和新增 IP 作为线索，不沿可疑账号继续递归扩大关联范围。「忽略本次」抑制已有提示，后续新活动可重新提示。IPv4 /24 提示默认关闭；开启 Subnet_alerts 后也只是低可信线索，必须人工审核。`192.168.*` 是私网地址，不能用来判定运营商或玩家归属；代理服还需正确配置真实 IP 转发。

## 面板布局

「关联账号处置与观察」分为「待核查提示 / 观察名单 / 处置记录」三个页签，分别显示数量。待核查卡片分离玩家、IP、依据、观察对象、最近活动和备注；观察名单在宽屏以卡片网格展示、手机单列展示；处置记录按需展开逐项执行结果、冲突及撤销信息。

成功加入观察后自动转到观察名单，完成封禁后转到处置记录。界面变化不改变人工确认、批量限制、权限或撤销规则。样式仅作用于该板块及其弹窗，兼容 Plan 默认日间/夜间模式；建议使用支持 CSS color-mix 的现代浏览器。

## 文件与备份

- 原玩家和地区数据仍在 Plan 数据库的 `plan_ip_information`，没有新增或删除玩家数据库字段。
- `plugins/Plan/ip-moderation.json`：独立的操作审计、撤销快照、观察名单和忽略记录。**必须随插件数据备份**，不要上传公开仓库或放入 public_html。
- Minecraft 服务根目录 `banned-players.json` / `banned-ips.json`：原生实际封禁名单。一起备份，勿用测试环境名单覆盖正式服。
- `/plan db move` 不迁移此独立 JSON。切换 SQLite / MySQL 时仍需保留它及服务器身份；跨机器迁移要随相同 Plan 实例复制。

升级时停服、完整备份 `plugins/Plan/` 和原生封禁文件，替换单个 Plan JAR、加入以上配置并启动。不要删除数据库、身份文件、网页用户或地区 .xdb 库。此实现不与第三方封禁插件的处罚存储同步。
